# Pancratzia publishing

The production origin is https://www.pancratzia.com. Keep the Site public.

## GitHub Pages publication

The user selected `Pancratzia/Portfolio`, branch `main`, as the website's
GitHub repository. Every completed website change must be committed and pushed
there so `.github/workflows/pages.yml` can publish it. Publishing in ChatGPT
Sites alone is not completion of a request to update the GitHub Pages website.
Use `python scripts/build-pages.py --base-path /Portfolio` to validate the
preview URL, or no base path for the custom domain. The production workflow
must run `python scripts/build-pages.py` without a base path because the custom
domain serves assets at `/`; never deploy `/Portfolio/` asset URLs there.
Preserve existing GitHub
repository files outside the current `dist/`, scripts and deployment config.
Never publish secrets, repository credentials or generated `_site` output.

Before EVERY source packaging/publication, run `python scripts/prepare-site.py`
after page edits or generation. Pass it as an ordered command to the Sites
source workflow helper: `["python", "scripts/prepare-site.py"]`.
It installs GTM-MJ25B2CM and GA4 G-8PBFVMNNQS once per page, updates URLs to
the custom domain, and regenerates sitemap.xml and robots.txt from actual
HTML pages. It includes English and Spanish pages and omits noindex pages.
The tracked .openai/sitemap-state.json preserves lastmod for unchanged pages.
Never publish a hand-maintained sitemap or omit this preparation command.
Preparation also rebuilds localized 404.html pages from the latest shared
navigation/footer and generates browser-language routing in locale.js.
The explicit language selector preference always overrides browser detection.

The checked-in dist/ tree is the current deployable website. For small edits,
edit dist directly and update matching source templates where applicable.
Do not regenerate all pages with legacy build.py for unrelated small changes.

## v3 redesign (November 2026) — CURRENT

The live design is generated by `python scripts/v3/build.py` (sources in
scripts/v3/: core.py chrome, pages_home.py, pages_main.py, legacy.py, base.css,
extra.css, site.js). It writes every page in EN and ES. Edit those sources,
then run build.py and prepare-site.py. build.py reads long-form copy (service
details, articles, legal) from the previous dist/, so to rebuild from scratch
restore dist/ to commit 06b4182 first, or edit those pages in dist directly.
Do not run redesign_studio.py or services_studio.py; they belong to the
previous design.

## Studio direction (November 2026, superseded by v3)

The current homepage is the bilingual ASCII studio redesign. Its source is
scripts/redesign_studio.py with dist/studio.css and dist/studio.js. Preserve
the curved draggable project carousel, clear Webflow positioning, simplified
navigation, and direct email contact. Pricing is on its own page, not the hero.

update its copy when editing those pieces. Do not run legacy homepage builders.

The hero carousel now contains ASCII service cards, never project screenshots
or a "Your next website" placeholder. Project screenshots belong in selected
work. Portraits are inline ASCII text from assets/laura-ascii.txt; do not render
a second portrait image or leave a source image in the page.
Run scripts/redesign_studio.py then scripts/services_studio.py when rebuilding
the studio pages. The latter maintains the services hub and nested specialties;
preserve all existing maintenance prices and localization add-on terms.
